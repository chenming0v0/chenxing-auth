# 首个管理员初始化设计

## 目标

数据库没有任何管理员时，用户首次打开 Web 前端应看到初始化界面，提交用户名和密码后创建首个 Owner 管理员。初始化完成后显示成功提示并跳转到管理员登录页；后续访问不得再次公开创建管理员。

## 方案

后端新增公开的 `GET /api/v1/admin/bootstrap/status` 状态接口，并调整现有 `POST /api/v1/admin/bootstrap` 的认证规则：只有 `admins` 表为空时允许匿名请求，已有管理员时返回 `409 bootstrap_already_completed`。创建逻辑继续使用现有 PostgreSQL advisory lock 和事务，确保并发请求只有一个成功。

前端在应用根入口查询初始化状态。状态未完成时渲染复用现有 `AuthShell`、`Starfield`、`Logo`、`Field` 和 `GlowButton` 的初始化页；状态完成时保留当前 Landing 页。提交成功后显示成功状态，短暂延迟后跳转 `/login`，不自动创建管理员 Session。

## 安全边界

- 状态接口只返回 `initialized` 布尔值，不返回管理员数量、邮箱或其他敏感信息。
- 匿名初始化只允许 `admins` 表为空时执行。
- 初始化用户名、密码和角色沿用现有管理员服务校验，角色固定为 `owner`，前端不暴露角色选择。
- 数据库 advisory lock 是并发控制的唯一权威；不能仅依赖前端状态或先查询再插入。
- 初始化完成后的请求不能被 `ADMIN_TOKEN` 或其他已有管理员认证绕过状态限制。

## 验证

- 集成测试覆盖未初始化状态、成功匿名创建、重复初始化冲突和状态切换。
- 服务级测试覆盖两个并发初始化请求最多一个成功。
- OpenAPI 验证覆盖两个公开接口的路径、请求、响应和错误码。
- 前端执行 TypeScript/Vite 构建，并使用本地浏览器检查初始化页、成功提示和登录跳转。
- 完成项目级 `src-line-limit` 检查，覆盖 `src` 与 `web/src`。
